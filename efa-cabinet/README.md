# EfA Cabinet — каркас личного кабинета (фаза 1)

Что уже есть: регистрация/логин, дашборд со списком проектов, карточка
проекта с загрузкой регламентов в приватное хранилище и местами-заглушками
под ссылку на опрос и готовый результат.

Чего here **нет** (сознательно, это следующие фазы):
- Telegram-бот и генерация `survey_token` — сейчас поле просто пустое,
  ссылка на опрос не появляется сама. Как только бот будет переделан на
  мультитенантную схему (`?start=<survey_token>`), останется дописать
  вызов, который сохраняет токен в `projects.survey_token`.
- Автоматическая сборка бизнес-архитектуры. Статус проекта переключает
  вручную Рустем (через Supabase Dashboard → Table Editor → projects,
  или SQL) на каждом шаге: `awaiting_docs` → `survey_open` → `processing`
  → `done`. Готовый файл заливается вручную в Storage-бакет `documents`
  (kind = `deliverable`) через тот же Dashboard.

## 1. Разверни Supabase

1. Зайди на supabase.com → New Project. Регион — ближайший к клиентам
   (Frankfurt подойдёт для РФ/СНГ).
2. Дождись создания, затем Project Settings → API — скопируй `Project URL`
   и `anon public` key, они понадобятся в `.env.local`.
3. SQL Editor → New query → вставь целиком содержимое
   `supabase/migrations/0001_init.sql` → Run.
4. Так же прогони `supabase/migrations/0002_storage.sql`.
5. Authentication → Providers → Email должен быть включён (по умолчанию
   так и есть). Если хочешь пропустить подтверждение почты на время
   тестирования — Authentication → Settings → отключи
   "Confirm email" (потом обязательно включить обратно для боевого
   контура).
6. Authentication → URL Configuration → Site URL укажи будущий адрес
   кабинета (например `https://app.ef-a.ru`), и туда же в Redirect URLs
   добавь `https://app.ef-a.ru/auth/callback`.

## 2. Настрой переменные окружения

```bash
cp .env.local.example .env.local
```

Заполни `NEXT_PUBLIC_SUPABASE_URL` и `NEXT_PUBLIC_SUPABASE_ANON_KEY`
значениями из шага 1.2. Добавь ещё одну переменную (её нет в примере,
но она нужна для писем подтверждения):

```
NEXT_PUBLIC_SITE_URL=https://app.ef-a.ru
```

Для локальной разработки — `http://localhost:3000`.

## 3. Установи зависимости и проверь локально

```bash
npm install
npm run dev
```

Открой `http://localhost:3000` — должно перекинуть на `/login`.
Зарегистрируйся, создай проект, загрузи любой файл — он должен появиться
в списке и в Supabase Storage под `documents/<твой_user_id>/<project_id>/`.

## 4. Задеплой на Vercel

1. Залей код в GitHub-репозиторий (или подключи прямо папку через
   Vercel CLI: `npx vercel`).
2. На vercel.com → New Project → импортируй репозиторий.
3. В Environment Variables добавь те же три переменные, что в `.env.local`.
4. Deploy.
5. Settings → Domains → добавь `app.ef-a.ru` (или другой выбранный
   поддомен) и пропиши CNAME у регистратора домена ef-a.ru согласно
   инструкции Vercel.
6. Вернись в Supabase → Authentication → URL Configuration и обнови
   Site URL / Redirect URLs на реальный адрес, если отличается от
   того, что указал в шаге 1.6.

Сама Tilda (ef-a.ru) не трогается — просто добавь на неё кнопку/пункт
меню "Личный кабинет" со ссылкой на `app.ef-a.ru`.

## 5. Как выглядит текущий ручной путь клиента (фаза 1 → фаза 2)

1. Клиент регистрируется, создаёт проект, загружает регламенты.
2. Рустем видит новые файлы в Supabase Storage/Dashboard → вручную
   меняет статус на `survey_open` и (пока вручную, до переделки
   `/telegram-survey-bot`) отправляет клиенту ссылку на опрос отдельным
   сообщением — либо, когда бот переделан на мультитенантность,
   прописывает `survey_token` через SQL, и ссылка сама появится в
   карточке проекта.
3. После сбора ответов Рустем как обычно прогоняет
   `/technoline-business-architecture` в сессии с Claude, используя
   загруженные регламенты + выгруженные ответы опроса.
4. Готовый HTML заливается в Storage-бакет `documents` с `kind =
   'deliverable'`, `project_id` = id проекта, `owner_id` = id клиента —
   через SQL-insert или отдельный админ-скрипт (в фазе 1 не входит,
   можно сделать по образцу `UploadForm.tsx`, только с фиксированным
   `kind`).
5. Статус проекта переключается на `done` — клиент видит кнопку
   "Скачать" в своём кабинете.

## Структура проекта

```
src/
  middleware.ts          — защита /dashboard/*, обновление сессии
  lib/supabase/client.ts — Supabase-клиент для 'use client' компонентов
  lib/supabase/server.ts — Supabase-клиент для серверных компонентов
  lib/statusLabels.ts    — человекочитаемые названия статусов проекта
  app/
    login/               — вход
    register/            — регистрация + страница "проверьте почту"
    auth/callback/       — обработка ссылки подтверждения email
    dashboard/           — список проектов, создание проекта
    dashboard/[projectId]/ — карточка проекта: файлы, опрос, результат
supabase/migrations/     — SQL-схема (прогнать в Supabase SQL Editor)
```

## Известные ограничения каркаса

- Нет валидации типов/размера загружаемых файлов на клиенте — сейчас
  Supabase Storage просто примет что дадут (лимит размера бакета можно
  настроить в Dashboard → Storage → documents → Settings).
- Один клиент = один аккаунт = свои проекты. Мультипользовательские
  компании (несколько сотрудников клиента с доступом к одному проекту)
  не предусмотрены — при необходимости это отдельная модель доступа
  (напр. таблица `project_members`).
- `npm install`/`npm run build` не проверялись в песочнице, где готовился
  этот каркас (нет доступа к npm registry) — прогони оба локально перед
  деплоем.
