# worker — обработчик ИИ-агентов EfA

Отдельный контейнер рядом с кабинетом. Кабинет ставит задание в таблицу `agent_jobs`, обработчик его выполняет и пишет ход работы, результат, файлы и расход моделей. Длинная сборка (30–60 минут) не держит запрос кабинета.

```
кабинет (Next.js)  ── insert agent_jobs ──▶  Postgres  ◀── забирает, пишет progress/result ──  worker (Python)
                                                                                                 │
                                                                     Yandex AI Studio ◀──────────┘
```

## Состав
| Файл | Что делает |
|---|---|
| `efa_agents/gateway.py` | Шлюз моделей по ролям: author — Alice AI LLM, mass — тоже Alice AI LLM (Flash не используем: качество важнее), auditor — gpt-oss-120b, fallback — YandexGPT 5.1 Pro. Повторы при 429/5xx, запасная модель при сбое или отказе отвечать, расчёт ₽. |
| `efa_agents/harness.py` | Обвязка: разбор JSON (в том числе слитые объекты), правки кодом, проверки, повтор с конкретными замечаниями (до 3 попыток), журнал шагов. |
| `efa_agents/auditor.py` | Аудитор v3: вопросы чек-листа «да/нет + цитата». Подтверждённые «нет» исправляются, спорные уходят консультанту. Исправление, которое ухудшило проверки кода, отбрасывается. |
| `efa_agents/business_architect/` | Агент «Бизнес-архитектор»: промпты, проверки разделов, сборка первой итерации и итерации по замечаниям. |
| `efa_agents/bpmn/` | Движок раскладки BPMN и генератор скрипта Sila Union (копия `skriptolog_sila/agents/bpmn`), проверка скрипта. |
| `efa_agents/store.py`, `worker.py` | Очередь в Postgres (`FOR UPDATE SKIP LOCKED`), обработчик, уведомления в Telegram. |
| `efa_agents/run_local.py` | Запуск без базы — для проверки. |

## Что строит «Бизнес-архитектор»
Оргструктура, цели и показатели, функции, процессы (ядро проверяется аудитором сразу, от него зависят остальные разделы). Затем параллельно: детальный ключевой процесс, риски и решения, реестр НМД, регулярные встречи, финансово-бюджетная структура, ИТ-архитектура, физические объекты, управление проектами, управление продуктами, паспорта руководителей. После этого — тексты двух документов и BPMN ключевого процесса с декомпозицией: верхний уровень и подпроцессы.

Итерация: на вход подаются `previous_job_id` и `remarks`. Модель решает, какие разделы затронуты замечаниями, и правит только их. Код затем находит разделы, где правка ядра сломала ссылки (владельцы, подразделения, id целей), и чинит их. Изменённые разделы снова проходят аудит.

## Запуск
Проверка без моделей:
```bash
python3 -m unittest discover -s tests
```
Полная сборка на ТехноЛайн без базы (≈ 400 ₽):
```bash
python3 -m efa_agents.run_local tests/fixtures/input_technoline.json out --env ../../03_yandex/keys.env
```
Обработчик (в контейнере):
```bash
docker build -t efa-worker worker
docker run -d --name efa-worker --env-file .env.worker --restart unless-stopped efa-worker
```
`.env.worker`: `DATABASE_URL`, `YC_API_KEY`, `YC_FOLDER_ID`, `TELEGRAM_BOT_TOKEN`, `TELEGRAM_CHAT_ID`. Файл хранится только на сервере, в git не кладётся.
